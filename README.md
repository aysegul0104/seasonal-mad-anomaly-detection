# Seasonal MAD Anomaly Detection in Synthetic Time Series

This project implements a small, reproducible anomaly-detection experiment on a synthetic one-dimensional seasonal time series. It compares a **seasonal MAD detector** (linear trend + sinusoidal seasonal fit + robust MAD thresholding) against a **moving-average baseline** on a chronological test split, reporting precision, recall, and F1.

The project is educational and CPU-only. It does not claim production readiness, and it does not guarantee that the algorithm will outperform the baseline; the measured result depends on the synthetic data and the specific seed/sample size.

## Problem

Given a 1-D time series that contains a linear trend, a dominant sinusoidal seasonal component, small Gaussian noise, and a sparse set of injected additive anomalies, the goal is to flag the anomalous points.

Two detectors are compared:

1. **Seasonal MAD (algorithm):**
   - Fit a linear trend and a sinusoidal seasonal component on the training split.
   - Compute residuals on the test split using the model learned on the training split.
   - Flag test points where `|residual| > 3 * 1.4826 * MAD(train residuals)`.

2. **Moving-average (baseline):**
   - Compute a centered 7-point moving average on the training and test splits.
   - Flag test points where `|deviation from MA| > 3 * std(train deviations)`.

Both detectors use **only training-split statistics** for their thresholds to prevent leakage. Metrics are computed on the last 25% of the series (chronological split, no shuffling).

## Architecture

The repository contains the following Python files:

- `data.py` – Generates the synthetic seasonal time series and binary anomaly labels.
- `app.py` – Implements the seasonal MAD detector, the moving-average baseline, and the experiment runner.
- `test_project.py` – Pytest test cases that validate the project behavior.
- `main.py` – Host-provided entry point (not part of this generated code).
- `requirements.txt` – Pinned dependencies.

The `run_experiment` function in `app.py` is the main entry point for the experiment. It:

1. Calls `make_dataset(seed, n_samples)` from `data.py`.
2. Splits the data chronologically into 75% train and 25% test.
3. Runs the seasonal MAD detector and the moving-average baseline.
4. Computes precision, recall, and F1 on the test split.
5. Returns a JSON-serializable dict with `n_samples`, `metrics`, `baseline_metrics`, and `explanation`.

## Synthetic Dataset

The dataset is fully synthetic and generated by `make_dataset` in `data.py`. It consists of:

- A linear trend with slope 0.05.
- A sinusoidal seasonal component with period 12 samples and amplitude 2.0.
- Small Gaussian noise with standard deviation 0.3.
- Sparse additive anomalies (spikes) with magnitude 5 * noise_std, placed randomly (but deterministically for a given seed) in the middle 90% of the series.

### Assumptions and Limitations

- The seasonal period is fixed at 12 samples.
- Anomalies are additive spikes, not multiplicative or structural breaks.
- The signal is fully synthetic; no real-world data is used.
- `make_dataset` is deterministic for a given `(seed, n_samples)` pair and performs no disk I/O.
- `n_samples` must be at least 32; otherwise, a `ValueError` is raised.

## Algorithm vs. Baseline

### Seasonal MAD (Algorithm)

1. **Trend fit:** A linear trend is fit using `np.polyfit` on the training split.
2. **Seasonal fit:** The dominant frequency is identified from the FFT of the detrended training signal. Amplitudes for sin and cos at that frequency are estimated by least-squares.
3. **Residuals:** Residuals are computed on the test split using the model learned on the training split.
4. **Threshold:** The threshold is `3 * 1.4826 * MAD(train residuals)`, where MAD is the median absolute deviation.
5. **Flagging:** Test points where `|residual| > threshold` are flagged as anomalies.

### Moving-Average (Baseline)

1. **Moving average:** A centered 7-point moving average is computed on the training and test splits.
2. **Deviations:** Deviations from the moving average are computed on the training split.
3. **Threshold:** The threshold is `3 * std(train deviations)`.
4. **Flagging:** Test points where `|deviation| > threshold` are flagged as anomalies.

### Metrics

- **Precision:** `TP / (TP + FP)`
- **Recall:** `TP / (TP + FN)`
- **F1:** `2 * Precision * Recall / (Precision + Recall)`

All metrics are in the range `[0, 1]`, with higher values indicating better performance. The metrics are computed on the test split only.

## Reproducibility

The project is deterministic for a given `(seed, n_samples)` pair. To reproduce the results:

1. Create a virtual environment:
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

2. Install dependencies:
   ```bash
   python -m pip install -r requirements.txt
   ```

3. Run the experiment:
   ```bash
   python main.py --seed 42 --n-samples 256 --output results.json
   ```

4. Run the tests:
   ```bash
   python -m pytest -q
   ```

The output of `run_experiment` is a JSON-serializable dict that can be saved to `results.json`. The `validation_report.json` and `example_results.json` files (if present) contain measured outputs for reference.

## Limitations

- The project is educational and not intended for production use.
- The synthetic data is simple and may not reflect real-world time series.
- The seasonal period is fixed; the algorithm does not adapt to different periods.
- The moving-average baseline uses a fixed window size of 7.
- The tests validate the project behavior but do not guarantee that the algorithm will outperform the baseline. The measured result depends on the synthetic data and the specific seed/sample size.
